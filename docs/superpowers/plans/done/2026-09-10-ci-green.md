## Design

Fix, don't suppress: no `skip`/`xfail`, no `continue-on-error`, no deleting a test that pins
live behavior. Each red test gets one of three treatments: it pins an archived upstream migration
→ retarget or drop that case; it pins the pre-Toman world → update the expectation, prod code
untouched; it catches a real bug → fix the code. The ruff cleanup is its own mechanical commit
before any logic commit, so every later diff stays readable.

**Out of scope:** the model-vs-DB schema drift below ("Found, not fixed"); the grace table (own
plan `2026-09-10-grace-access-sessions-table.md`); CryptoBot's ruble-based rate
(`_get_usd_to_rub_rate`, replaced by a later payment plan); Phase C; making checks *required*
(a ruleset — the user's call); Node 20 deprecation warnings; `pip-audit`/`npm audit` findings
(already non-blocking); CodeQL (green).

## Found, not fixed (goes into PR B's body)

**Model-vs-database schema drift.** Measured 2026-09-10 against the dev DB (alembic head `0112`)
by diffing `Base.metadata` with `information_schema.columns`:
- `guest_purchases` lacks `campaign_slug` and `idempotency_key` — both used by live code
  (`app/cabinet/routes/gift.py:449–463`, `app/handlers/subscription/gift.py:706/904/918`), and any
  ORM `SELECT` of `GuestPurchase` names every mapped column, so gift/guest purchase flows on a
  migrated database likely fail with `UndefinedColumn`.
- Missing tables: `grace_access_sessions` (own plan), `referral_reward_levels` (deliberately
  deferred), `coupons`, `coupon_batches`, `legal_consents`, and the deferred-gateway tables
  `recurrent_payments`, `cispay_payments`, `lava_subscriptions`, `platega_subscriptions`.

Fresh installs get all of these via `create_all`; databases migrated through our Alembic chain
don't, and CI can't see it (the tests use `create_all`/SQLite). This is a migration, so it's
architectural: recommend a separate plan next, including a guard test ("every mapped column exists
after `alembic upgrade head`").
